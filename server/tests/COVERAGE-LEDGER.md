# Coverage-Parity Ledger (FR-057)

This ledger records every test method of the 56 test files under `server/tests/` at commit `26c89af`, before the microservices redesign, plus one file-level row per support class. It shows where each legacy assertion lives now and which gate last verified it. `architecture/CoverageParityLedgerTest` (T134) enforces it.

## Columns

- **Legacy file**: the path under `server/tests/` at `26c89af`, without `.java`.
- **Method**: the legacy `@Test` method. `(file)` marks a support class. A bracketed suffix names one assertion of a method that has its own status.
- **Status**: one of the statuses below.
- **Owner (gate)**: the task that writes the replacement, and in parentheses the gate that must verify it: Foundational, US2, US1, US3, US5, US4, US6, or US7, in that order.
- **Replacement**: the `File#method` list, relative to `server/tests/`, that holds the equivalent assertions. A `planned:` entry is not checked until the row leaves `PENDING`.
- **Requirement or equivalence note**: the governing requirement, which a `SUPERSEDED` row must cite, or why the replacement is equivalent.
- **Verified at**: the gate task whose run last passed this test or its replacement.

## Statuses

- `RETAINED`: the file stays unchanged and keeps passing.
- `ADAPTED`: the file stays at its path and is edited in place, keeping every method and assertion.
- `PENDING`: the replacement is not written yet.
- `MIGRATED`: equivalent assertions exist in the replacement methods.
- `SUPERSEDED`: the assertion encodes behavior that the spec replaces. The replacement asserts the specified behavior, and the row cites the governing requirement.

## Rules

- A task that writes a replacement updates its rows.
- A task that breaks a legacy file moves it to `server/tests-legacy/`, keeping its relative path. A replacement written at the same path moves the original there first.
- Legacy files are deleted only after verified parity (T130). T130 passed `PARITY_GATE=final` on 2026-10-23, then deleted all 27 parked files one by one, rerunning `CoverageParityLedgerTest` after each deletion; `server/tests-legacy/` no longer exists.
- `PARITY_GATE=<gate> server/run-tests.sh` fails while a row owned by that gate, or by an earlier one, is `PENDING`, or while a row owned by an earlier gate lacks `Verified at`. `PARITY_GATE=final` requires every row to be non-`PENDING` with a `Verified at` value.

## Feature 006 (gRPC → events)

This section records every test method of the test files under `server/tests/` at commit `8891c57` that feature 006 edits, replaces, or deletes while it replaces gRPC with Kafka-carried events, plus one file-level row per support class. It shows where each assertion goes and which gate verifies it (FR-065). `architecture/CoverageParityLedgerTest` (T043) enforces it separately from the feature 005 section above.

### Columns and statuses

The columns and statuses are those of the feature 005 section, with these differences:

- **Legacy file**: the path under `server/tests/` at `8891c57`, without `.java`.
- **Method**: a bracketed suffix names one assertion of a method, or one later task's edit of it, that has its own status, owner, and gate. A method edited by tasks of different gates has one row per edit: the unbracketed row records the first edit.
- **Owner (gate)**: the task that writes the replacement or the adaptation, and in parentheses the gate that must verify it: Foundational, US1, US3, US4, US5, US2, US6, US7, or US8, in that order.
- **Requirement or equivalence note**: every row cites its governing requirement. A note may say "planned SUPERSEDED" for a `PENDING` row whose task is expected to supersede it.
- **Verified at**: the gate task whose run last passed this test or its replacement; blank until that gate runs.

### Rules

- A task that writes a replacement or adapts a file updates its rows. A `PENDING` row's method must stay in its file until its row leaves `PENDING`, unless another row of the same method is already `MIGRATED` or `SUPERSEDED`.
- There is no parking directory. A legacy file is deleted only after every one of its rows is `MIGRATED` or `SUPERSEDED` and names replacements that exist; the gate run then fills `Verified at`. A row that leaves `PENDING` drops its `planned:` prefix.
- Every test source that still references gRPC, generated gRPC contracts, the `rpc` package, `GrpcTestSupport`, or an `InventoryGateway` has rows here: method rows for its `@Test` methods, or a `(file)` row for a support class.
- A feature 005 row whose replacement method, or whose `RETAINED` or `ADAPTED` method, this feature removes stays valid while this section has a `MIGRATED` or `SUPERSEDED` row for that file and method.
- `PARITY_GATE=006:<gate> server/run-tests.sh` fails while a row of this section owned by that gate, or by an earlier one in this section's order, is `PENDING`, or while a row owned by an earlier gate lacks `Verified at`. `PARITY_GATE=006:final` requires every row of this section to be non-`PENDING` with a `Verified at` value. Gates without the `006:` prefix (`US2`, `final`, and so on) keep meaning the feature 005 section.
